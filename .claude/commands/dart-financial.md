# /dart-financial $ARGUMENTS

`$ARGUMENTS`의 첫 토큰은 회사명, 둘째 토큰은 사업연도(없으면 `get_latest_reports`로 최근 사업보고서를 고른다)다.
dart MCP 툴로 사업보고서의 재무 파트를 읽고 **재무 심층분석 보고서**를 작성한다. CLAUDE.md 공통 원칙을 따른다.

> **원칙: 숫자는 API, 서술은 원문.** 재무제표 본표 숫자는 `get_key_financials` / `get_financial_statements`에서 가져온다.
> 원문 III장의 요약재무정보·재무제표 본표(4.1, 4.2 등)는 읽지 않는다. 원문은 배당·자금조달·주석(차입금 만기·이자율,
> 충당부채, 우발, 특수관계자)·경영진단 같은 서술과 API에 없는 세부에만 쓴다.

## (a) 읽기 순서

### 보고서 선택 (사업연도를 생략했을 때)

사업연도 인자가 없으면 `find_company` 다음에 **`get_latest_reports(corp_code)`**를 호출한다.
- `latest_annual`의 bsns_year를 사업연도로 쓰고, **본문 outline·섹션·검색은 `body_rcept_no`로, 감사보고서(첨부 00760/00761)는 `attachment_rcept_no`로** 읽는다. 정정 ZIP에는 바뀐 부분만 있다([첨부정정]·[첨부추가] ZIP엔 본문이 없고, [기재정정] ZIP엔 감사보고서가 없을 수 있다). 머리의 정정 표시는 `rcept_no`(최신본) 기준, 출처 `(rcept_no, section_id)`의 rcept_no는 실제로 읽은 접수번호(본문이면 body_rcept_no)다. `superseded`는 쓰지 않는다. 사업연도를 명시해 search_disclosures로 고를 때도 같은 규칙: 본문은 꼬리표 없음·[기재정정] 중 최신, 감사보고서는 꼬리표 없음·[첨부정정]/[첨부추가] 중 최신 접수본.
- outline 응답의 `parse_warnings`가 비어 있지 않으면(예: "SECTION-1 14개 중 4개만 파싱됨") 원문 뒷부분이 빠졌을 수 있다. 보고서 머리에 그 경고를 그대로 적고, 목차에 없는 장은 "원문 파싱 누락으로 확인 불가"로 둔다.
  이 경우 search_disclosures로 사업보고서를 다시 찾지 않는다.
- `interim_after_annual`이 비어 있지 않으면 **가장 마지막** 항목의 bsns_year·reprt_code로
  `get_key_financials(corp_code, <bsns_year>, reprt_code=<reprt_code>, period_type="cumulative")`를 호출해
  "최근 분기 동향" 소절에 쓴다(아래 고정 목차 참고).
- **정정본 표시**: 선택된 사업보고서의 `correction_kind`가 `"기재정정"`이면(연도를 명시해 search_disclosures로 고른 경우는
  report_nm에 "[기재정정]"이 있으면) 보고서 머리 출처 줄 앞에 `[기재정정본, 접수일 YYYY-MM-DD]`를 적는다. 그리고
  `search_in_disclosure(rcept_no, "정정사유")`로 원문 첫 섹션(정정 사유 표)을 찾아 그 위치만 읽고 **한 줄로 요약**해 머리 아래에 둔다
  (예: "정정 사유: 연결재무제표 주석 오기 정정 (<rcept_no>, <section_id>)"). 첨부정정·첨부추가는 머리 표시 없이 부록에만 적는다.
- **늦은 정정(`late_corrections`)**: 비어 있지 않으면 "8. 종합 의견"(이 커맨드에는 리스크 절이 없다)에 한 줄:
  "최신 사업보고서 접수 후 과거 기간 정정 공시 N건(<kind> <period> <correction_kind>, rcept_no …) — 전기 재무제표 재작성 가능성".
  기재정정이 있으면 3개년 표의 전기·전전기 값이 정정 전 기준일 수 있음을 함께 적는다(재무 API는 `refresh=True`로 다시 받는다).
사업연도를 명시했으면 기존 방식대로 그 연도 사업보고서를 쓰고, 최근 분기 동향 소절은 생략한다.

1. `find_company` → (사업연도 생략 시) `get_latest_reports` / (명시 시) `search_disclosures(..., pblntf_ty="A")` → 사업보고서 body_rcept_no(본문)·attachment_rcept_no(감사보고서).
2. 재무 숫자는 API로 받는다 (원문 4.1/4.2 읽기 생략):
   - `get_key_financials(corp_code, <사업연도>)` → 3개년 핵심 계정 + 영업이익률·순이익률·부채비율·자기자본비율·ROE·ROA.
   - `get_financial_statements(corp_code, <사업연도>, sj_div="BS,IS,CIS")` → 매출총이익, 유동자산·유동부채, 차입금·사채 계정.
     현금흐름 세부가 필요하면 `sj_div="CF"`. 모두 원 단위이며 당기·전기·전전기 3개년이 한 번에 온다.
   - 연결(CFS)에 데이터가 없으면(status 013 message) `fs_div="OFS"`로 다시 부르고 보고서에 별도 기준임을 적는다.
3. `get_disclosure_outline(body_rcept_no)` 기본 depth로 "III. 재무에 관한 사항"의 하위 id를 확정하고, 서술 섹션만 읽는다 (각 1회):

| 순서 | 섹션(제목 기준) | 목적 |
|---|---|---|
| 1 | III > 6. 배당에 관한 사항 | 배당 정책·배당성향 |
| 2 | III > 7. 증권의 발행을 통한 자금조달 | 유상증자·사채 발행 실적 |
| 3 | IV. 이사의 경영진단 및 분석의견 | 실적·유동성 변동 요인 (숫자는 API 값과 대조만) |

4. 주석은 통째로 읽지 않는다. `get_disclosure_outline(body_rcept_no, file_id="main", depth=3)`으로
   "3. 연결재무제표 주석"의 소제목(id가 `.tN`)을 받아, 제목에 아래 키워드가 들어간 소제목만 골라
   `get_disclosure_section(rcept_no, "<id>.tN")`으로 읽는다. 소제목 제목으로 못 찾으면
   `search_in_disclosure(rcept_no, "<키워드>")`로 위치를 찾는다.
   - "차입금" (단기·장기차입금, 사채)
   - "충당부채"
   - "우발" (우발부채, 약정사항)
   - "특수관계자"
   읽을 소제목이 30,000자를 넘으면 max_chars를 나눠 읽되, 표의 합계 행 중심으로 발췌한다.

## (b) 보고서 고정 목차

파일: `reports/<회사명>_재무분석_<YYYY-MM-DD>.md`

```
# <회사명> 재무 심층분석 (<사업연도> 사업보고서 기준)
> [기재정정본, 접수일 YYYY-MM-DD] (기재정정일 때만) 출처 공시: rcept_no <rcept_no>, 접수일 <rcept_dt> / 연결 기준 여부 명시 / 작성일 <오늘>

## 1. 요약
(5줄 이내)

## 2. 수익성
(표: 매출액, 매출총이익, 영업이익, 당기순이익, 매출총이익률, 영업이익률, 순이익률, ROE, ROA — 3개년.
 금액은 재무 API 값을 백만원으로 환산. 비율은 "계산". ROE·ROA는 평균자본·평균자산 기준이며
 ratios.roe.basis("지배주주 기준"/"연결 총액 기준")를 행 이름에 붙인다. 12월 결산이 아니면 periods.range를 표 머리에)

## 3. 안정성
(표: 자산총계, 부채총계, 자본총계, 부채비율, 유동비율, 차입금 합계, 순차입금 — 3개년 또는 가능한 연도.
 차입금 상세: 주석 차입금 항목에서 단기/장기/사채 구분과 만기·이자율 범위)
**get_key_financials의 flags에 "capital_impairment"가 있으면 이 표 바로 아래에 "자본잠식(자본총계 음수): <연도>"를 한 줄로 명시**하고
해당 연도 부채비율·자기자본비율·ROE 칸은 "n/a(자본잠식)"으로 둔다.

## 4. 현금흐름
(표: 영업·투자·재무활동 현금흐름, 유형자산취득(CAPEX 대용), 기말 현금 — 3개년, 재무 API.
 자유현금흐름 = 영업활동현금흐름 − 유형자산취득, "계산"으로 표기)

### 최근 분기 동향 (<reprt_nm> <bsns_year>, 누적)
(get_latest_reports로 사업보고서 이후 반기·분기보고서가 있을 때만. 재무 추이 표 **뒤에 별도 표**로 둔다.)
| 지표 (백만원 / %) | <bsns_year> 누적 | 전년 동기 누적 | 증감률(계산) |
매출액·영업이익·당기순이익·영업활동현금흐름·영업이익률(계산)·순이익률(계산). 재무상태표 계정(자산·부채·자본·부채비율)은
"당기말 vs 전기말(<직전 사업연도>말)" 열 이름을 따로 단 두 번째 표로만 쓰거나 생략한다.
- 분기 수치는 **전년 동기와만** 비교한다. 연간 표의 열에 넣거나 연간 수치와 증감률을 계산하지 않는다. 연환산 금지.
- 표 머리에 기간을 정확히: 예) "2026.01–2026.06 누적 vs 2025.01–2025.06 누적 (백만원, 연결, 재무API)".
- 출처 `(<분기·반기 rcept_no>, 재무API)`. 서술(변동 요인)이 필요하면 원문을 더 읽지 말고 "원문 미확인"으로 둔다.
## 5. 배당 및 자금조달

## 7. 특수관계자 거래
## 8. 종합 의견
(재무 건전성에 대한 판단 3~5줄. 투자 권유 문구 금지. late_corrections가 있으면 재작성 가능성 한 줄)

## 부록. 참조한 섹션 목록
```

## (c) 인용 규칙

/dart-analyze와 동일하다(원문 숫자 인용 규칙 포함: 단위 행 확인, 통화·단위 혼합 금지, 확신 없으면 짧게 원문 인용). 특히:
- 범위는 `4–5배`(en dash)로 쓴다. `~`를 한 단락에 두 번 쓰면 Markdown 취소선이 되어 "45배"로 보인다.
- 재무 API 숫자는 `(rcept_no, 재무API)`로 출처를 적는다. 주석 숫자는 `(rcept_no, 4.3.tN)`처럼 원문 위치를 적는다.
- 모든 수치에 `(rcept_no, section_id)` 출처. 소제목에서 가져온 수치는 `.tN` id까지 적는다.
- 계산한 비율·순차입금·자유현금흐름은 "계산" 표기, 원문에 없는 판단은 "추정:" 표기.
- 연결/별도 기준을 섹션마다 확인하고 섞이면 표마다 기준을 적는다.
- 표는 핵심 행만. 주석 표는 합계 행 위주로 발췌하고 원문을 길게 복사하지 않는다.
- 같은 섹션은 한 번만 읽는다. 끝나면 보고서 본문, 툴 호출 횟수, 읽은 총 글자 수를 채팅에 보고한다.

## (d) 마지막 단계: 독립 리뷰 (필수, 1회)

보고서를 저장한 뒤 `.claude/commands/dart-review.md`의 "실행 방식"대로 한다:
1. Agent 툴(`general-purpose`)로 리뷰어 서브에이전트를 띄운다. prompt에는 dart-review.md에 적힌 단락에 보고서 경로만 넣는다.
   **작성 과정의 대화·읽은 내용은 넘기지 않는다.**
2. 리뷰어가 `reports/<보고서명>.review.md`를 쓰면 FAIL 항목을 반영해 보고서를 고치고, 보고서 맨 끝에 `## 리뷰 반영 내역` 표를 붙인다.
3. 리뷰를 다시 돌리지 않는다. 채팅 보고에 선택된 보고서(사업연도·rcept_no, 분기보고서), 리뷰 PASS/FAIL 현황, 고친 항목,
   **툴 호출 횟수와 읽은 글자 수를 작성/리뷰로 나눠** 적는다.
