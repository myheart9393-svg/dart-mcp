# /dart-analyze $ARGUMENTS

`$ARGUMENTS`의 첫 토큰은 회사명, 둘째 토큰은 사업연도(없으면 `get_latest_reports`로 가장 최근 사업보고서를 고른다)다.
dart MCP 툴로 사업보고서를 읽고 **종합 기업분석 보고서**를 작성한다. 분석 주체는 너(Claude)다.
읽기 전에 반드시 이 프로젝트의 CLAUDE.md 공통 원칙을 따른다.

> **원칙: 숫자는 API, 서술은 원문.** 재무 숫자(매출·이익·자산·부채·자본·현금흐름·비율)는 `get_key_financials`
> (필요하면 `get_financial_statements`)에서만 가져온다. 원문 III장(요약재무정보·재무제표 본표)은 읽지 않는다.
> 원문은 사업 구조·경영진 시각·리스크·지배구조 같은 서술 부분에만 쓴다.

## (a) 읽기 순서

### 보고서 선택 (사업연도를 생략했을 때)

사업연도 인자가 없으면 `find_company` 다음에 **`get_latest_reports(corp_code)`**를 호출한다.
- `latest_annual`의 rcept_no·bsns_year를 분석 대상 사업보고서로 쓴다(정정본이 있으면 이미 정정본이 선택돼 있다. `superseded`는 쓰지 않는다).
  이 경우 search_disclosures로 사업보고서를 다시 찾지 않는다.
- `interim_after_annual`이 비어 있지 않으면 **가장 마지막** 항목의 bsns_year·reprt_code로
  `get_key_financials(corp_code, <bsns_year>, reprt_code=<reprt_code>, period_type="cumulative")`를 호출해
  "최근 분기 동향" 소절에 쓴다(아래 고정 목차 참고).
사업연도를 명시했으면 기존 방식대로 그 연도 사업보고서를 쓰고, 최근 분기 동향 소절은 생략한다.

1. `find_company(회사명)` → stock_code가 있는 정확 일치 회사의 corp_code를 고른다. 애매하면 사용자에게 묻는다.
2. (사업연도를 명시한 경우만) `search_disclosures(corp_code, "<사업연도+1>0101", "<사업연도+1>1231", pblntf_ty="A")`
   → report_nm이 "사업보고서 (<사업연도>.12)"인 항목의 rcept_no. "[기재정정]"본이 있으면 정정본을 쓴다.
   (12월 결산이 아닌 회사는 report_nm의 결산월을 보고 기간을 넓혀 다시 검색한다.)
3. `get_key_financials(corp_code, <사업연도>)` → 3개년 핵심 계정과 계산 비율 (연결 CFS 기본.
   message에 status 013 안내가 오면 `fs_div="OFS"`로 재호출하고 보고서에 별도 기준임을 적는다).
   missing에 든 계정은 표에 "-"로 두고, 꼭 필요하면 `get_financial_statements(..., sj_div="BS")`처럼 해당 표만 받아 계정명을 찾는다.
4. `get_disclosure_outline(rcept_no)` (기본 depth=2) → 아래 섹션의 실제 id를 제목으로 대조해 확정한다.
   id 번호는 회사마다 다를 수 있으므로 **제목 기준**으로 찾는다.
5. 섹션을 아래 순서로 읽는다. 각 섹션은 **한 번만** 읽고, char_count가 30,000을 넘으면 통째로 읽지 말고
   `search_in_disclosure`로 필요한 부분만 찍어 읽는다.

| 순서 | 섹션(제목 기준) | 목적 |
|---|---|---|
| 1 | I. 회사의 개요 > 1. 회사의 개요 | 법적 실체, 사업부문 구성 |
| 2 | II. 사업의 내용 > 1. 사업의 개요 | 사업 구조, 매출 구성 |
| 3 | IV. 이사의 경영진단 및 분석의견 | 경영진의 시각, 전망, 실적 변동 요인(숫자는 API 값과 맞는지 대조만) |
| 4 | II. 사업의 내용 > 7. 기타 참고사항 | `search_in_disclosure(rcept_no, "시장점유율")`, `(..., "경쟁")`으로 위치를 찾고 그 부근만 읽는다 |
| 5 | XI. 그 밖에 투자자 보호 > 2. 우발부채 등, 3. 제재 등 | 리스크 |
| 6 | VII. 주주에 관한 사항 | 최대주주·지분 구조, 소액주주 비율 |

## (c) 인용 규칙

- 범위는 `4–5배`(en dash)로 쓴다. `~`를 한 단락에 두 번 쓰면 Markdown 취소선이 되어 "45배"로 보인다.
- 숫자와 사실을 쓸 때는 문장 끝에 **반드시** 출처를 붙인다: `(rcept_no, section_id)` 예) `(20250311001085, 5)`, 재무 API 값은 `(20250311001085, 재무API)`.
  같은 단락에서 같은 출처가 반복되면 단락 끝에 한 번만 붙여도 된다.
- 원문에 없는 해석·추정은 문장 앞에 **"추정:"** 을 붙인다. 계산한 비율은 "계산"이라고 쓴다.
- 원문을 길게 복사하지 않는다. 문장은 요약하고, 표는 핵심 행만 발췌한다(재무 표는 10행 이내).
- 재무 API 숫자의 출처는 `(rcept_no, 재무API)`로 적는다. 원문 숫자와 API 숫자가 다르면 API 값을 쓰고 차이를 각주로 남긴다.
- **원문 숫자 인용 규칙** (주석·경영진단 등 원문에서 숫자를 옮길 때):
  - 단위는 반드시 그 표의 단위 행(예: "(단위: 백만원)", "(단위: USD 천)")에서 확인하고 숫자 옆에 함께 적는다.
    단위 행을 못 봤으면 그 숫자를 쓰지 않는다.
  - 통화와 단위를 섞은 표현 금지. ✗ "USD 3,653억원" → ✓ "미 달러화 환율 5% 변동 시 세전손익 영향 N백만원(원문 표 단위)"
    (원문 표가 원화 금액이면 통화명은 '어느 통화의 변동인지'로만 쓰고 금액 단위는 원화 단위로).
  - 원문 단위를 임의로 바꾸지 않는다. 억원·조원으로 바꿨다면 "(백만원 → 조원 환산)"처럼 밝힌다.
  - 확신이 없으면 숫자를 풀어 쓰지 말고 원문 문장을 짧게(한 문장 이내) 그대로 인용한다.
- 단위를 항상 쓴다(백만원/억원/주/%).
- 같은 섹션을 세션 중 두 번 읽지 않는다. 이미 읽은 섹션은 기억에서 쓴다.
- 보고서를 저장한 뒤, 채팅에는 보고서 본문 전체와 함께 **호출한 MCP 툴 횟수**와 **읽은 총 글자 수**
  (get_disclosure_section의 returned_chars 합 + search_in_disclosure의 context 글자 합)를 보고한다.

## (d) 마지막 단계: 독립 리뷰 (필수, 1회)

보고서를 저장한 뒤 `.claude/commands/dart-review.md`의 "실행 방식"대로 한다:
1. Agent 툴(`general-purpose`)로 리뷰어 서브에이전트를 띄운다. prompt에는 dart-review.md에 적힌 단락에 보고서 경로만 넣는다.
   **작성 과정의 대화·읽은 내용은 넘기지 않는다.**
2. 리뷰어가 `reports/<보고서명>.review.md`를 쓰면 FAIL 항목을 반영해 보고서를 고치고, 보고서 맨 끝에 `## 리뷰 반영 내역` 표를 붙인다.
3. 리뷰를 다시 돌리지 않는다. 채팅 보고에 선택된 보고서(사업연도·rcept_no, 분기보고서), 리뷰 PASS/FAIL 현황, 고친 항목,
   **툴 호출 횟수와 읽은 글자 수를 작성/리뷰로 나눠** 적는다.
