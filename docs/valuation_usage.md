# 가치평가 사례 DB 사용법 (회계사용)

`reports/valuations/*.json`은 DART 합병·분할·주식교환·IPO 공시에서 평가 주체별 방법·가정·결론을 뽑은 사례다
(2026-10-27 기준 161건: 합병 67·IPO 64·분할 15·주식교환 12·분할합병 3, 공시 기간 2024-01–2026-10. 2024–2025는 합병·분할·교환만, IPO 없음). 조회는 Claude Code에서
`/dart-valuation-search <조건>`(자연어)로 하거나 아래 CLI를 직접 쓴다. CLI는 **거래 단위** 통계다: 한 거래에 값이 여럿이면
외부평가기관 값이 대표값(없으면 그 거래 값들의 중앙값). 결과는 항상 "N건 거래, M개 값"으로 읽는다.

```bash
uv run python -m dart_mcp.valuation stats reports/valuations [--from --to --deal-type --method --purpose --industry --regime
    --firm X --as 외부평가|재무자문|any --status --exclude-status --spac true|false|unknown]
uv run python -m dart_mcp.casedb compare reports/valuations [필터…] --wacc 11 --g 1 --srp 3.5 --beta-l 1.0 [--n 3]
uv run python -m dart_mcp.casedb export reports/valuations --csv 사례.csv [필터…]   # 평가 요소 1행, UTF-8 BOM(엑셀)
```

## 조회 예시 5개

| # | 질문 | 명령 | 결과(2026-10-27) |
|---|---|---|---|
| 1 | 업종별 WACC | `stats … --method DCF --industry 29` (KSIC 코드 접두, 2자리=중분류. 결과 `industries`에 중분류 라벨별 거래 수) | 29 기타 기계·장비: 8건 거래, WACC 중앙값 11.88%(Q1–Q3 11.26–13.09%). 다른 중분류는 DCF 거래 4건 이하 |
| 2 | 특정 평가기관의 사례 | `stats … --firm 이촌` (그 기관이 **평가 주체인 원소만**, 기본 `--as 외부평가`; 재무자문까지 보려면 `--as any`) | 12건 거래·13개 값, WACC 중앙값 11.12%(8.43–17.59%), g 중앙값 1.0%. v1.5까지는 같은 거래의 다른 기관 값이 섞였다(이촌 26개 값) |
| 3 | IPO 비교기업 선정 | `stats … --deal-type ipo` → `ipo.multiple_types`, 각 사례 JSON의 `ipo.peers[]`·`excluded_multiples` | 64건: PER 51·EV/EBITDA 10·PSR 2·PBR 1. PER 중앙값 24.96배, 할인율 하단·상단 중앙값 23.9%·37.8%. 비교기업명·배수는 `ipo.peers[]`(25건에 있음) |
| 4 | 본질가치 가중 | `stats … --method 본질가치` → 사례 JSON의 `valuations[].weights`·`asset_value`·`income_value` | 18건 거래·54개 원소. 가중치는 전부 자산 1 : 수익 1.5(시행세칙 제4조). 예: 보원케미칼(한미회계법인) 자산 2,133원·수익 8,197원 |
| 5 | 민감도 범위 | 사례 JSON의 `sensitivity[]` (`variables` 문구 + `range.min/max`) | 68개 표. 예: 보원케미칼(한미회계법인) WACC 10.77–11.77%·g 0.50–1.50% → 1주당 수익가치 7,210–9,396원 |

- 업종은 기업개황 induty_code(조회 시점) 기준이다. 중분류 라벨은 `src/dart_mcp/ksic.json`(KSIC 10차). 소프트웨어는 58 출판업 안의 582다.
- 합병·분할·주식교환은 **반드시 `--regime`을 준다.** 2026.12.9 이후 이사회 결의분부터 공정가액 체계라 기준시가 사례와 한 분포로 보지 않는다
  (두 체계가 섞이면 결과에 `warning`). IPO는 `--deal-type ipo`만으로 충분하다.
- 공정가치평가(RCPS 등)·손상검사 원소는 기본값에서 빠진다. 넣으려면 `--purpose all`.
- **선례 대비 내 가정의 위치**: `casedb compare`가 변수별 분포(n·중앙값·Q1–Q3)와 내 값의 백분위, 표준화 거리 최근접 선례 N건(접수번호·기관·SPAC·상태)을 준다.
  예: 제조업 합병 DCF(기준시가, 2023-10-27 이후, 철회 제외) — WACC 11.0% 백분위 54, 규모위험 3.5% 36, βL 1.0 61, 최근접 바이오포트·셀로맥스사이언스·엔비알모션(모두 SPAC).
- **SPAC 합병**은 `deal.spac`(파생)으로 가른다(`--spac false`). 합병 70건 중 SPAC 36 — 섞으면 g(SPAC 1.0% 일색)와 WACC 분포가 SPAC 쪽으로 기운다.
- 업종은 대분류로도 묶인다: `--industry 제조업`(KSIC 10–34), `정보통신`(58–63), `금융보험`(64–66), `도소매`(45–47), 또는 대분류 문자 `C`.
- 합병·분할·교환 사례에는 `deal.status`(진행·완료·철회·중단·미확인)가 있다. 철회 건도 통계에 남고 `statuses`로 따로 센다 — 평가보고서에 인용할 때 철회 여부를 함께 적는다.
- 원문 자체가 산식에 안 맞는 사례는 `source_inconsistent`에 표시돼 있다(10건). 그 숫자를 인용할 때는 원문의 다른 값과 함께 확인한다.

## 평가보고서에 인용할 때

모든 숫자에는 `cite = {rcept_no?, file_id, section_id, offset}`와 원문 표기 `text`가 있다. 인용은 다음 형식으로 쓴다.

> 보원케미칼 합병(한미회계법인) 민감도 1주당 수익가치 7,210–9,396원
> (출처: DART 접수번호 20260102000205, 「II. 합병 가액 및 그 산출근거」(section 5), offset 150323·150265, 원문 표기 "7,210"·"9,396")

- **접수번호**: cite에 rcept_no가 없으면 사례의 `rcept_no`. DART 뷰어 `https://dart.fss.or.kr/dsaf001/main.do?rcpNo=<접수번호>`에서 연다.
- **섹션 제목**: 사례 JSON `citations[]`에서 같은 section_id의 title. `file_id`가 main이 아니면 첨부 파일명도 적는다.
- **offset**은 dart-mcp가 변환한 섹션 텍스트 기준 글자 위치다(`get_disclosure_section(rcept_no, section_id, offset=…)`로 재현).
  DART 뷰어의 위치가 아니므로, 뷰어에서는 `text`(원문 표기)로 찾는다.
- 거래 단위 통계를 인용하면 조회 조건·기준일·"N건 거래, M개 값"을 함께 적는다
  (예: "2026-01–10 DART 합병 공시 기준시가 체계 DCF 14건 거래(55개 값), 거래별 대표값 중앙값 11.09%, dart-mcp 사례 DB 2026-10-27").

## 인용 규칙 (통계를 평가보고서에 쓸 때)

1. **표본이 거래 20건 미만이면 중앙값 대신 개별 선례 표를 먼저 쓴다.**
   - 표는 `stats … --list`나 `casedb compare … --list`로 만든다. 열은 회사, 접수번호, 결의일, SPAC, 상태, WACC, g, 규모위험, 자산가치 총액이다.
   - 중앙값은 표 아래 참고로만 붙인다.
2. **숫자에는 항상 네 가지를 함께 적는다.**
   - n(거래 수, "N건 거래, M개 값")
   - 범위(최소–최대 또는 q1–q3)
   - SPAC 여부(`--spac`)
   - 상태(진행·완료·철회·중단 포함 여부)
   - 예: "비SPAC 합병 DCF 14건 거래(진행 6·철회 1 포함), WACC 중앙값 10.35%, q1–q3 8.56–13.01%".
3. **SPAC과 비SPAC은 나눠서 본다.** SPAC 합병은 비상장 피합병법인 평가라 가정이 다르다. 합친 분포는 인용하지 않는다(`--spac false` / `--spac true`).
4. **대형사와 소형사가 섞여 있는지 확인한다.** 대한항공·SK이노베이션 같은 대형 상장사(WACC 5–9%, 규모위험 0)와 코스닥 소형사(규모위험 3–5%)가 한 분포에 들어 있다.
   개별 선례 표에서 규모·규모위험 열을 보고, 내 대상과 비슷한 선례를 따로 짚는다.
5. **`중앙값 안정성` 경고가 있으면 중앙값을 쓰지 않는다.** 이 경고는 거래 1건만 빼도 중앙값이 ±10% 넘게 움직인다는 뜻이다. 개별 선례 표로 설명한다.
   - 경고가 없어도 경계에 가까울 수 있다. 그럴 때는 `median_stability`의 범위(min–max)를 함께 적는다.

**예: 거래 1–2건에 중앙값이 움직인다(2026-11-04, 비SPAC 합병 DCF WACC).**

| 표본 | 거래 수 | WACC 중앙값 | 1건씩 뺀 중앙값 범위 |
|---|---|---|---|
| v1.6.2 (샘표 추가 전) | 13 | 11.28% | 10.35–11.38% |
| 샘표 추가(현재) | 14 | 10.35% | 9.42–11.28% (±9.0%, 경고 한계 10% 바로 아래) |
| 샘표·SK이노베이션 제외 | 12 | 11.38% | 11.28–11.48% |
| (v1.6.3 보고값 — 같은 SK 거래를 두 번 셈) | 15 | 9.42% | — |

샘표(8.45%) 한 건이 들어오자 중앙값이 0.9%p 내려갔다. v1.6.3에서는 SK이노베이션 정정본 사례가 같은 거래로 한 번 더 들어가 11.28 → 9.42%로 보고됐다
(v1.6.4부터 통계는 같은 거래의 정정본 하나만 쓴다 — `정정본으로 대체된 사례` 경고).
이런 표본에서 "합병 DCF WACC 중앙값 약 10%"라고만 쓰면 오해를 부른다. 개별 선례 표와 n·범위를 같이 적는다.
재현: `uv run python -m dart_mcp.valuation stats reports/valuations --deal-type merger --method DCF --spac false --list`, 특정 거래를 빼려면 `--exclude-rcept 20261102000312,20261028000313`.

## 한계

- **summary 등급은 가정이 없다.** 주요사항보고서만 있는 사례는 평가의견서 첨부가 API ZIP에 없어 결론 5행뿐이고 WACC·g·β·멀티플이 null이다.
  분포에는 들어가지 않고 표에는 "원문 없음"으로 남는다(현재 89건 중 1건).
- **통계는 참고용이다.** 표본이 2026년 10개월치이고 IPO에 쏠려 있다(합병 DCF 14건 거래). 거래 10건 미만 조회는 "통계적 의미 제한".
  업종은 중분류 하나에 DCF 거래 5건 이상인 곳이 29(기계) 하나뿐이다. 평가기관·주관사의 판단을 대신하지 않는다.
- **원문 확인 필수.** 추출은 LLM이 하고 무작위 20%만 독립 리뷰했다(배치 18건 PASS). `validate`의 `warnings`(WACC 0–30% 밖, g ≥ WACC,
  g > 5%, 멀티플 ≤ 0, 할인율 0–70% 밖, 자산가치 합계 불일치)는 2026-10-27 현재 4건(원문 표 합계 불일치 3·확인 필요 1)이고, 값이 범위 안이라고 맞는 값은 아니다.
  평가보고서에 쓰는 숫자는 DART 원문에서 직접 확인하고 원문을 출처로 적는다. 사례 DB는 찾는 도구이지 출처가 아니다.
- 단위는 원문 그대로다(원·백만원·%·배). 합산·비교 전에 `unit`을 맞춘다.
- **규모위험은 "적용" 값만 통계에 들어간다.** 원문이 미적용을 명시한 0.00%는 `size_premium_applied=false`로 표시돼 빠지고 결과의 `size_premium_not_applied`로 센다.
  규모와 별도로 더한 고유위험·성장성 가산은 `specific_risk`(별도 변수, compare `--specific`). 원문 라벨이 "Firm Specific Risk"여도 근거가 KICPA 규모위험이면 size_premium이다.
- **null은 0이 아니다.** 규모위험·비교회사·상대가치·수익가치가 비어 있으면 `absent_reasons`에 이유가 있다("원문에 없음"·"추출 안 함"·"해당 없음",
  키워드 감사 기준). "추출 안 함"인 건은 원문을 직접 확인한다. β 산정 방식·규모위험 근거·거래 단위 상대가치는 v1.6 스키마에 칸만 있고 기존 사례는 비어 있다.
